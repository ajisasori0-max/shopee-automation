## Commands Executed

```bash
# Create virtual environment and install dependencies
python3 -m venv .venv
. .venv/bin/activate
pip install sqlalchemy alembic python-dotenv pydantic pydantic-settings

# Initialize Alembic (after removing pre-existing migrations directory)
alembic init migrations

# Configure alembic.ini, migrations/env.py to import commerceos models

# Generate initial migration
alembic revision --autogenerate -m "initial canonical commerce schema"

# Apply migration
alembic upgrade head

# Verify tables
python - <<'PY'
from commerceos.platform.database.connection import get_engine
from commerceos.config.settings import settings
from sqlalchemy import inspect
engine = get_engine(settings.database_url, echo=False)
inspector = inspect(engine)
for table in inspector.get_table_names():
    print(table)
PY

# Seed reference data
python - <<'PY'
from commerceos.platform.database.connection import get_session
from commerceos.config.settings import settings
from commerceos.commerce.models import Organization, Business, Marketplace
session = get_session(settings.database_url, echo=False)
org = Organization(name="Gerard Commerce", slug="gerard-commerce")
session.add(org)
session.flush()
business = Business(name="Gerard Shopee Store", organization_id=org.id, default_currency="IDR")
shopee = Marketplace(code="shopee", name="Shopee Indonesia")
session.add_all([business, shopee])
session.commit()
print(f"Organization: {org.id}")
print(f"Business: {business.id}")
print(f"Marketplace: {shopee.id}")
PY

# Backup database
chmod +x scripts/backup_db.sh
./scripts/backup_db.sh
```

## Failures Encountered

1. `alembic revision` failed initially because `commerceos/commerce/models.py` was a file while `models` was expected as a directory. Resolution: removed `models.py`, moved code into `models/__init__.py`.
2. SQLAlchemy `MappedAnnotationError` because `TimestampMixin` and `TenantMixin` used `Column[]` instead of `Mapped[]`. Resolution: updated mixins to use `Mapped` and `mapped_column`.
3. Seeding failed because `org.id` was not generated until flush. Resolution: flushed organization before assigning its ID to business.

## Remaining Technical Debt

- Domain models and persistence models are currently the same SQLAlchemy classes. ADR-002 documents this debt.
- Many platform modules (`events`, `logging`, `health`, `validation`) are only scaffolding with `__init__.py` files.
- No formal unit tests yet.
- Old databases (`growth_data.db`, `financial_data.db`) are not migrated yet.
- Commerce State is modeled but not yet built or populated.

## Rollback Procedure

```bash
# Reverse the migration
alembic downgrade -1

# Or delete the generated database and regenerate
rm commerceos.db
alembic upgrade head

# Old databases remain untouched; legacy scripts continue to work.
```
