## Modifications Applied

1. **Renamed `EncryptedFileProvider` to `LocalFileProvider`**: Base64 was misleading; the new name accurately reflects a plaintext local development fallback.
2. **SecretManager is fully provider-agnostic**: It knows only the `SecretProvider` interface.
3. **Secrets are namespaced**: `shopee/{store_id}/partner_id`, `shopee/{store_id}/partner_key`, etc.
4. **Connector contract first**: `MarketplaceConnector` interface defines business capabilities, not endpoints.
5. **Standardized connector responses**: `ConnectorResult` with `success`, `data`, `errors`, and `metadata`.
6. **Incremental synchronization**: `SyncMode` enum with `FULL` and `INCREMENTAL`; incremental is default.
7. **Raw payload preservation**: Contract requires connectors to retain original marketplace payloads alongside canonical mapping (raw store implementation pending).
8. **Connector health**: `ConnectorHealth` exposes deterministic health information (auth, API availability, last sync, rate limits, token expiry, data freshness).
9. **Revised ADR-003**: Marketplace Connector Interface updated to reflect the above decisions.

## Design Decisions

- `LocalFileProvider` is explicitly plaintext. It is for local development only. Production must use a KMS-backed provider.
- `SecretManager` has no default provider list; it accepts any `Sequence[SecretProvider]`.
- `ShopeeAuth` requires `store_id`, making multi-store support natural.
- `MarketplaceConnector` interface is now the canonical contract for all marketplaces.
- `ConnectorResult` and `ConnectorHealth` are the only integration points for orchestration and observability.
- Raw payload preservation is a contract obligation; the raw store is a future Sync Engine responsibility.

## Trade-offs

| Decision | Pros | Cons |
|----------|------|------|
| Plaintext `LocalFileProvider` | Accurate name, no misleading security claims | Not secure; production needs KMS |
| Namespaced secrets | Multi-store ready, no redesign | Longer secret names |
| Connector contract first | New marketplaces plug in cleanly | Interface may evolve as we integrate more APIs |
| Standardized result/health | Uniform orchestration/observability | Adds a small amount of boilerplate |
| Raw payload preservation | Debuggable, replayable, future-proof | Increases storage |

## Remaining Technical Debt

- `LocalFileProvider` is not production-grade. Replace with a KMS-backed provider.
- No secret rotation, expiration, or audit logging.
- Raw payload store is not yet implemented.
- Health check implementations are shallow until real API telemetry exists.
- Cloud providers (AWS Secrets Manager, GCP Secret Manager, Azure Key Vault, HashiCorp Vault) are future work.
